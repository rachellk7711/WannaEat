## 1. 결론

Codex 보고서의 **확인 가능한 주장을 전부 독립 재검증했고, 모두 사실이었다.**
수치까지 일치한다. 반박할 지점을 찾지 못했다.

핵심 판단에도 동의한다.

> 우선 할 일은 DB 추가 수집보다 **원료를 연결하는 규칙과 근거를 요약하는 과정의 오류를 고치는 것**이다.
> 더 많은 자료를 같은 규칙으로 합치면 잘못된 연결도 늘어난다.

이 문장이 지금 상황을 정확히 요약한다. 지난 작업에서 나는 자료를 계속 넓혔다 —
FDA 3,971종, JECFA 126+530종, EU 412종, K-FIND 31.6만 건.
그런데 **넓힐수록 같은 결함이 같은 배율로 커졌다.**

다만 범위는 분명히 해 둔다. Codex도 적었듯 이것은 전면 폐기가 아니다.
원본(`data/raw/`)은 문제가 없다. 문제는 **연결 규칙과 요약 방식**이다.

```

  790  홍경천추출물       사용불가      →  "제한 없음"

   …
```

원인은 `scripts/09_build_evidence_candidates.py` 의 이 두 줄이다.

```python
kr_use = (k.get("USE_CND_STDR_CN") or "").strip()
```

`USE_CND_NM` 칸에 `사용가능 / 사용불가 / 제한적사용` 이 따로 있는데 읽지 않았다.
금지를 허용으로 뒤집는 방향의 오류라 공개 전에 반드시 막아야 한다.

## 3. Codex 보고서가 짚지 않은 것

재검증 중에 추가로 확인한 것들이다.

### 3-1. B 결함의 두 번째 결과 — 평가 대상별 기록이 합쳐졌다

population 칸이 항상 공란이라, `07` 의 중복 제거 키 `(substance, population)` 가
사실상 `(substance, "")` 로 동작했다. **물질명 하나당 한 행만 남는다.**

원 기록의 대상 분포는 이렇다.

```
ADI 원 기록 1,153건
   consumers  1,148
   adults         3
   infants        1
   children       1
```

건수는 적지만 성격이 나쁘다. 에리스리톨에서 이미 확인했듯 EFSA 는
**어린이 섭취를 별도로 지적하는 경우**가 있다. 대상이 다른 평가는 합치면 안 된다.

### 3-2. B 결함은 문서의 약속도 깨뜨렸다

`docs/17_성분군_지도.md` §4 에 내가 이렇게 썼다.

> 그래서 `efsa_adi.csv` 에 `basis` 칸을 만들어 EFSA 원문의 근거 문장을 함께 싣는다.

그 칸은 **804행 전부 비어 있다.** 즉 "아질산 0.07은 아질산 이온 기준" 같은
기준 표기 문제는 **손으로 쓴 `evidence_manual.csv` 안에서만 해결됐고,
자동 산출물에서는 해결되지 않았다.** 문서가 데이터보다 앞서 나갔다.

### 3-3. 집계 라벨이 사실과 다르다

`09` 의 요약 출력이 `EFSA 5종 / 둘다 104종` 이라고 찍는데,
그 `국제 상태` 칸에는 지금 JECFA 값과 사람 확정값도 함께 들어온다.
**EFSA 만의 수치가 아니다.** 내가 이전 보고에서 이 숫자를 EFSA 기준으로 말한 적이 있다.
라벨을 고치기 전까지 이 수치를 인용하지 않는다.

### 3-4. C 결함의 원인 — 검사 순서

`10_build_allergen_map.py` 는 `직접` 을 먼저 검사한다.

```python
if any(k in t for k in direct):   hits["직접"].append(...)
elif any(k in t for k in guess):  hits["추정"].append(...)
```

`새우향` 은 `추정` 목록에 넣어뒀지만, `직접` 목록의 `새우` 가 먼저 걸린다.
Codex 가 "순서만 뒤집는 것으로는 부족하다" 고 한 지적에 동의한다.
`새우향` 같은 **구체적인 토큰 규칙이 넓은 부분 일치보다 먼저** 적용돼야 한다.
순서만 바꾸면 `새우살` 같은 정상 사례가 추정으로 내려간다.

## 4. 이견과 보완

전면 반박할 지점은 없었다. 다만 두 가지를 덧붙인다.

### 4-1. 수정 우선순위를 "공개 위험" 기준으로 다시 세운다

Codex 의 5단계는 구조적으로 옳지만, 실행 순서는 **사용자에게 잘못된 정보가 나갈
위험** 순으로 잡는 편이 낫다고 본다.

| 위험 | 결함 | 왜 급한가 |
|---|---|---|
| **높음** | A 사용불가 → 제한 없음 | 금지를 허용으로 뒤집음 |
| **높음** | C 향·선택 표현이 알레르겐 `직접` | 안 들어간 것을 들어갔다고 말함 |
| 중간 | B EFSA 대상·기준 소실 | 값은 맞으나 의미가 빠짐 |
| 중간 | E 포괄명 축소 | 다른 물질의 근거가 붙음 |
| 낮음 | D EU 노드 135개 | 조건 일부 누락, 방향은 보수적 |

A·C 는 **틀린 값을 내보내는** 쪽이고, B·D 는 **덜 말하는** 쪽이다. 앞을 먼저 막는다.

### 4-2. Codex 의 "주장 단위 검토" 제안을 지지한다

같은 행 안에서 ADI 는 사람이 확인했고 EU 조건은 자동 생성된 경우가 실제로 있다.
행 단위 `사람 확인` 라벨로 둘 다 승인된 것처럼 보이는 구조는 지금 그대로다.
근거를 **주장(claim) 하나 단위**로 쪼개고 각각에 출처·검토 상태를 붙이자는 제안은
지금 구조에서 나온 문제를 정확히 겨눈다.

다만 이것은 스키마 설계에 직접 영향을 준다. **DB 설계는 사용자 검토 영역**이므로
여기서 확정하지 않고 요구사항으로만 남긴다.

## 5. 합의된 수정 순서

Codex 안을 위험도 기준으로 재배열한 것이다.

**0단계 — 공개 경로를 먼저 막는다**
`evidence_candidates.csv` 를 성분 카드·판정에 쓰지 않는다. 지금 상태로는 A·C 가 그대로 나간다.

**1단계 — 스냅샷과 회귀 사례**
현재 파일의 해시·행수를 기록한다. 최소 회귀 사례: 쑥(사용불가)·락툴로즈(제한적사용)·
새우향·우유향·땅콩또는견과류가공품·비타민b·소르비탄지방산에스테르·
대상이 여럿인 ADI. **정상 사례도 함께 넣는다** — 고치다가 매칭이 통째로 사라지는 것을 막기 위해서다.

**2단계 — A·C 수정 (틀린 값을 막는다)**
- `09`: `USE_CND_NM` 을 읽는다. 공란은 `제한 없음` 이 아니라 `조건 정보 미확인` 이다.
- `10`: 토큰 단위 구체 규칙을 부분 일치보다 먼저 적용한다. 향·선택 표현은 함유 확정으로 올리지 않는다.

**3단계 — B·E 수정 (의미를 복원한다)**
- `07`: 필드 경로를 고치고, 물질명 단위 축약을 제거한다. 대상·단위가 다른 평가를 합치지 않는다.
- `16`/`09`: 포괄명이 특정 물질로 좁혀지는 연결에 `범위 불일치` 표시를 남긴다.

**4단계 — D 및 출처 보존**
EU 조건 노드의 제외 사유를 기록한다. JECFA 조회는 원 응답·URL·시각을 남긴다.

**5단계 — 주장 단위 근거 구조 설계**
검토 후 스키마 확정. 이 단계는 사용자 검토가 선행한다.

## 7. 값·출처 검증 에이전트 결과 (2026-09-16 추가)

4개 검토 중 **값·출처 대조 1건이 완료**됐다. 나머지 3건(매칭·코드·문서)은 주간 사용 한도로
중단됐고 재실행 대기 중이다.

### 7-1. DOI 는 전건 정상이었다

내가 가장 걱정했던 부분이다. Crossref 대조 결과 **21개 DOI 전부 기재한 문서로 정확히
해석**됐다. 추측으로 넣은 DOI는 없었다. INCHEM 4건은 TRS 참조번호까지 일치했다.

표현 기준(basis of expression)도 지적했던 5건 모두 정확했다.
아질산 0.07(아질산이온) · 사카린 9(유리 이미드) · 글루탐산 30(글루탐산) ·
인산염 40(인) · 스테비올 4(스테비올 당량).

### 7-2. 값이 실제로 틀린 것 — 3건

**① 카라멜색소 — 3배 과대 적용 (내가 재확인함)**

EFSA 2011 은 그룹 ADI 300 과 **별도로 Class III(E150c)에 개별 ADI 100** 을 뒀다.
구성성분 THI 의 면역독성 불확실성 때문이다. 그런데 우리 행은 300 하나만 두고
별칭에 `카라멜색소Ⅲ`·`카라멜색소ⅲ` 를 포함했다.

`카라멜색소ⅲ` 는 우리 제품 DB에 **13,545회** 등장한다. 그 성분에 3배 높은 한도가 붙는다.

**② 소르비톨 — 기관을 잘못 적었다**

우리 행은 기관이 `EFSA`, 연도가 `2012` 인데, 인용한 문장 자체가
"SCF 와 JECFA 가 불필요하다고 판단했다" 고 말한다. **EFSA 의 결론이 아니다.**
EFSA 는 소르비톨(E 420) 재평가를 아직 발표하지 않았다 — 감미료 재평가가 진행 중이다.
2012 는 평가연도가 아니라 OpenFoodTox 레코드 일자로 보인다.

이것은 §3-1 에서 내가 짚은 "물질명 단위 축약" 과 다른 결함이다.
**출처 귀속 자체가 틀렸다.**

**③ 폴리글리시톨시럽 — 결론을 절반만 인용해 뜻이 뒤집혔다 (내가 재확인함)**

EFSA 2009 원문은 한 문장으로 이어진다.

> …insufficient to establish an ADI, **but based on the available data concludes that
> there are no indications of a safety concern for the proposed uses and use levels.**

우리는 앞 절만 잘라 `자료 부족` 으로 분류했다. 원문은 **긍정 의견**이고 그래서 EU 에서
E 964 로 승인됐다. 지금 표기는 EFSA 가 부정 평가한 것처럼 읽힌다.

에이전트가 이 건의 DOI 를 `확인 불가` 로 남겼는데, 내가 확인했다 —
**10.2903/j.efsa.2009.1413** 이다.

이 건은 §2 의 C(알레르기 오탐)와 성격이 같다. **틀리게 말하는** 쪽이다.

### 7-3. 값·DOI 는 맞으나 결론 문구가 원문과 어긋나는 것 — 5건

| 성분 | 우리 문구의 문제 |
|---|---|
| 에리스리톨 | EFSA 는 "급성·만성 노출 추정치가 **모두 ADI 를 상회**" 라고 결론했다. 우리는 "어린이가 음료로 섭취할 때" 로 좁혔는데 원문에 그런 한정이 없다 |
| 식용색소청색제1호 | "6 을 확인" 이 아니라 **SCF 의 10 을 대체한 신규 ADI 6** 이다 (NOAEL 631 × UF 100) |
| 파프리카추출색소 | 24 와 1.7 은 **기준이 둘이 아니라 같은 ADI 를 다른 단위로 쓴 것**이다 (카로티노이드 7.1%: 24 × 0.071 = 1.7). 내가 "기준이 둘" 이라고 쓴 것이 틀렸다 |
| 폴리인산나트륨 | 원문은 "protective for **the human population**" 이다. 내가 "건강한 성인에게는" 으로 좁혔다. 또 "식품보충제를 통한 노출이 ADI 를 초과한다" 는 지적이 빠졌다 |
| 자당(설탕) KDRIs | 총당류 20 은 상한이 아니라 **에너지적정비율(범위)** 이다. 20 만 적으면 범위의 하한이 사라진다. 원문 PDF 직접 확인 필요 |

파프리카 건은 특히 새겨둘 만하다. `docs/17` §4 에 내가 이것을
"같은 성분에 기준이 둘인 사례" 로 적었는데, **사례 자체가 잘못된 예시였다.**

### 7-4. 경미한 것

- 식용색소황색제5호: 원문은 NOAEL 이 아니라 **NOEL** 375
- MSG: NOAEL 3,200 은 **MSG 기준**, ADI 30 은 글루탐산 기준 — 두 기준 병기 필요
- 결정셀룰로스: 별칭 `카복시메틸셀룰로스칼슘` 은 EFSA 2018 대상 10종에 없다 (EU 미승인)
- 만니톨: 1966 은 잠정이 아니라 **조건부(conditional)**
- 알룰로오스: 게재는 2025;23(6) 6월 — 우리 표기 "2025-04" 와 불일치 가능
- 치자황색소: 내용은 맞으나 **검증 가능한 링크가 없다.** 부재를 출처로 삼은 형태다

### 7-5. 이 결과가 §5 수정 순서에 주는 변화

값이 틀린 3건(카라멜·소르비톨·폴리글리시톨)은 **사람이 확정했다고 표시된 행**이다.
자동 산출물이 아니다. 즉 `data/curated/evidence_manual.csv` 도 검토 대상이다.

따라서 2단계에 다음을 추가한다.

> **2-c. 사람 확정값 재검토** — 카라멜색소 Class III 분리, 소르비톨 기관 정정,
> 폴리글리시톨 결론 문장 복원. 그리고 결론 문구를 **원문 인용으로 대체**한다.
> 요약하는 과정에서 범위가 좁아지거나 뒤집힌 사례가 5건 더 나왔다.

원문을 그대로 싣기로 한 원칙이 있었는데, 한국어로 옮기면서 내가 해석을 섞었다.
그것이 이번 오류의 공통 원인이다.

**에리스리톨 — 검증 에이전트도 빠뜨린 문장이 있었다**

**KDRIs — 검증 에이전트의 지적은 틀렸고, 우리 연도가 틀렸다**

에이전트는 "20 은 에너지적정비율 범위이므로 20 만 적으면 하한이 사라진다" 고 했다.

### JECFA 조회 보완

- **식용색소 번호명 대응.** `Food Red No.40` 같은 이름은 마침표 때문에 API 가 리다이렉트(302)를 주고,
  성공해도 JECFA 는 국제명을 쓰므로 적중하지 않는다. 번호명 → 국제명 대응(청색1호 = Brilliant Blue FCF,
  적색2호 = Amaranth, 적색3호 = Erythrosine, 적색40호 = Allura Red AC, 황색4호 = Tartrazine,
  황색5호 = Sunset Yellow FCF)을 넣었다. 6종 모두 연결됐다 (적색3호 0~0.1 · 적색2호 0~0.5 · 황색5호 0~4 ·
  적색40호 0~7 · 황색4호 0~10 · 청색1호 0~6 mg/kg bw). 균주 학명(마침표 포함)은 JECFA 대상이 아니라 건너뛴다.
- **조회 기록.** 적중한 것만 저장해서 실행할 때마다 700여 건을 다시 물었다. `jecfa_query_log.csv` 에
  모든 조회(요청명·응답 건수·적중·시각)를 남기고 다음 실행은 건너뛴다. 704건 기록.
- JECFA 연결 144종 → **152종** (등장 8.1%). 적중 누적 134건.
- 한 번은 내가 `timeout 300` 을 걸고 실행해 175건에서 끊겼다. 제한 없이 다시 돌렸다.

### 말토덱스트린

국내 마스터에 일반 식품용 말토덱스트린의 **현행 기록이 없다.**

| 자료 | 기록 |
|---|---|
| I2520 | 건강기능식품(C코드) · 기능성원료 · 유효 |
| I2520 | 식품유형 · 가공식품 · **2015-06-16 만료** (USE_YN=N) |
| I1020 | 건강기능식품(C코드) · **사용불가 · 전량수출용** |

식품유형 `덱스트린` 기록은 유효하지만, 말토덱스트린이 그 유형에 해당한다는 것을 식품공전 원문으로
확인하지 않았으므로 연결하지 않았다. 대신 `09` 가 건기식 기록만 있는 원료의 상태를
`건기식 기록뿐(사용불가) — 일반 식품 기준 아님` 으로 적어, 수출용 사용불가가 일반 식품 기준처럼 읽히지 않게 했다.
성분 사전(`04`)의 분류도 `기능성원료` 로 잡혀 있다 — 판정 규칙(`18`)은 분류를 쓰지 않으므로 영향은 없다.
