# 데이터 검증 결론과 문제 해소 방안

> 작성자: Codex (OpenAI)
> 작성일: 2026-09-16
> 검증 기반: 4개 서브에이전트의 읽기 전용 검토 + Astra의 핵심 쟁점 독립 재검증.
> 상태: 해결 방안 제안. 아래 수정·재생성·적재는 아직 실행하지 않았다. 서비스 스키마는 검토 후 확정할 영역이다.

## 1. 결론과 적용 범위

현재 확보한 원본은 활용할 가치가 있다. 우선 할 일은 DB 추가 수집보다 **원료를 연결하는 규칙과 근거를 요약하는 과정의 오류를 고치는 것**이다. 더 많은 자료를 같은 규칙으로 합치면 잘못된 연결도 늘어난다.

`evidence_candidates.csv`를 그대로 성분 카드나 서비스 판정에 쓰는 것은 보류한다. 제품 검색용 데이터, 출처를 보존한 원자료 열람, 비공개 검증용 적재는 각각의 품질 조건을 확인하며 계속 진행할 수 있다. 모든 데이터를 폐기하거나 프로젝트 전체를 중단하라는 뜻은 아니다.

현재 파일의 역할은 다음과 같다.

| 위치 | 역할 | 검증 결과의 의미 |
|---|---|---|
| `data/raw/` | 받은 원본 | 보존하고 변환 오류를 복구하는 기준 |
| `data/prepared/` | 파싱·매칭·집계한 작업용 중간 산출물 | 형식·행수 검증과 의미 검증을 각각 수행해야 함 |
| `data/curated/` | 사람이 작성·확정한 값 | 확인한 주장과 범위를 보존해야 하며, 자동으로 덧붙은 필드까지 승인된 것은 아님 |
| Supabase 서비스 테이블 | 아직 적재하지 않았다고 공유된 서비스 DB | 이번 검토에서 원격 DB 상태를 직접 조회한 것은 아님 |

## 2. 확인된 사실

아래 수치는 2026-09-16 검토 당시 파일 기준이다. 원본이나 중간 산출물이 갱신되면 다시 측정해야 한다.

| 영역 | 확인 결과 | 판단 |
|---|---|---|
| 제품 변환 | `products.csv` 1,686,542행. 보고번호 중복 없음. 필수값 누락·중복·101개 충돌 ID 제외 규칙으로 행수 설명 가능. 원본 6건 필드 표본 대조 일치 | 기본 변환 무결성은 긍정적. 실물 라벨 정확성의 증명은 아님 |
| K-FIND | 원본 시트 차원상 데이터 316,734행, 출력도 316,734행. 첫 2행의 선택 25열 대조 일치 | 전수 셀 일치 검사는 아님. 보고번호가 유일키인지 별도 검증 필요 |
| 국내 사용조건 | Astra가 현재 후보 생성의 선택 규칙을 재현했을 때 사용불가 10건·제한적사용 4건이 후보에서 `제한 없음`으로 표시됨 | 공개 차단 사유. 이것을 전체 원본의 금지·제한 건수와 혼동하면 안 됨 |
| EFSA | 수치 ADI 원 기록 1,153건 → 출력 804건. 출력 population·basis 각각 804건 전부 공란. 필드 경로 오류 확인 | 349건 차이 전부를 오류로 단정할 수는 없지만, 현 축약 방식은 평가별 의미 보존을 입증하지 못함 |
| 식별자 | `비타민b → Riboflavin`, 포괄명 `소르비탄지방산에스테르 → Sorbitan Monostearate` 등 특정 물질로 좁히는 연결 확인 | 뒤에서 CAS가 일치해도 최초 이름 연결의 모호성이 해결되지 않음 |
| 알레르겐 | `우유향`, `새우향`, `땅콩또는견과류가공품`이 `직접`으로 기록됨 | 이름 기반 추정과 해당 제품의 함유 확인을 구분해야 함 |
| 통합 후보 | 5,940행 중 확보 경로가 자동인 행 5,879개, 사람 확인인 행 61개 | 61은 후보 행수이지 수동 원본의 성분 수가 아님. 행 전체의 검토 완료도 의미하지 않음 |
| EU 조건 | 1차 검토에서 조건 노드 2,387개 중 출력 2,252개. 반복 leaf를 첫 값으로 축약하는 코드 확인 | 노드 제외 사유와 반복 조건 보존을 재검증해야 함. 차이 135개를 모두 유효 조건 누락으로 단정하지 않음 |

4개 검토는 계보, 과학 평가, 규제·사용조건, 식별자·알레르겐으로 범위를 나눴다. Astra는 국내 상태 표현, EFSA 필드·출처 연결, 식별자·알레르겐, 주장별 검토 상태를 독립 재검증했다. Astra가 제품·K-FIND 행수를 다시 센 것은 아니다. 이번 검토는 모든 기관의 최신 평가서를 전수 확인한 인증이 아니다.

## 3. 수정 순서

### 1단계 — 기준 파일을 고정하고 회귀 사례를 만든다

수정 전 원본·중간 CSV의 파일명, 바이트 수, SHA-256, CSV 파서 기준 행수, 생성 스크립트 버전, 실행 시점을 manifest에 기록한다. 원본 확보일을 모르면 추정하지 않고 미상으로 남긴다. 수정 출력은 별도 실행 디렉터리에 만들고 검증 후 교체한다.

이미 발견한 오류를 먼저 테스트로 고정한다. `사용불가 + 조건 공란`, `제한적사용 + 조건 공란`, `비타민b`, `소르비탄지방산에스테르`, `우유향`, `새우향`, 복수 ADI·단위·대상이 있는 평가가 최소 사례다. 정상 연결 사례도 함께 넣어 수정으로 매칭 전체가 사라지는 것을 방지한다.

완료 기준: 같은 입력과 코드로 같은 출력을 재현하고, 변경 전후 행수·값·연결의 차이를 설명할 수 있다.

### 2단계 — 원료 동일성부터 확정한다

관련 코드: `04_build_dictionary.py`, `09_build_evidence_candidates.py`, `16_link_by_identifier.py`.

현재 `표준명`이나 동일한 영문명 하나가 여러 기관 근거를 끌어오는 출발점이다. 여기서 틀리면 이후 출처와 CAS가 아무리 정교해도 다른 물질의 근거가 붙는다.

- 토큰의 원문, 매칭 후보 전부, 원본 레코드 ID, 매칭 방식, 선택 이유를 보존한다. 사전에 먼저 들어온 행이나 분류 우선순위만으로 모호한 후보를 확정하지 않는다.
- `동일 물질`, `상위군/하위 물질`, `유래 원료`, `이름 유사`, `확인 불가`를 다른 관계로 다룬다. 상위군에 속한다는 이유로 하위 물질의 ADI를 상속하지 않는다.
- CAS는 형식·체크디지트와 원 출처를 확인하되, 체크디지트 통과를 물질 동일성 검증으로 취급하지 않는다. 염·이성질체·혼합물·그룹 평가의 범위도 확인한다.
- INS/E번호의 접미사·하위번호·범위·복수값을 보존한다. 첫 번째 숫자만 뽑아 다른 레코드와 결합하지 않는다. 번호 체계 간 대응도 출처와 범위를 확인한다.
- 영문명의 쉼표·괄호·기호가 물질명 자체의 일부일 수 있으므로, 일괄 분할·삭제로 새로운 별칭을 만들지 않는다.
- 식물성 원료는 통용명뿐 아니라 종·사용 부위·가공 형태까지 필요할 수 있다. 같은 별칭만으로 사용조건을 옮기지 않는다.

완료 기준: 카드에 공개할 연결에 미해결 다중 후보나 범위 축소가 없고, 알려진 오매핑 회귀 사례가 모두 검토 대기로 남거나 올바르게 수정된다.

### 3단계 — 기관별 원 기록의 의미를 복원한다

이 단계의 파서 수정은 원료 매칭 수정과 병행할 수 있다. 최종 병합은 두 단계가 모두 완료된 뒤 수행한다.

| 대상 | 수정안 | 완료 기준 |
|---|---|---|
| 국내 I1020/I0950 | 사용 상태와 조건 원문을 별도 보존. 조건 공란은 `조건 정보 미확인`. 공전 수록과 특정 용도 허용을 분리 | 원본의 금지·제한 상태가 소실되지 않고, 공란에서 `제한 없음`을 생성하지 않음 |
| EFSA `07` | Population·comments 필드 경로 수정. ToxRef 원 ID·SUB ID·평가기관·대상·기준물질·값·단위·한정자·원문 보존. 물질명별 최신 한 행 선택 제거 | 각 원 기록의 보존·중복 제외·제외 사유를 추적할 수 있고, 대상·단위가 다른 평가를 합치지 않음 |
| EFSA 문헌 연결 | 물질의 최신 dossier를 모든 ADI의 근거로 붙이는 방식 중단. 직접 연결이 확인된 평가서만 확정 출처로 사용 | 직접 연결이 불명확하면 `문헌 연결 미확인`으로 남기며, DOI 연도를 ADI 평가연도로 추정하지 않음 |
| EFSA 비수치 결론 | remarks를 원문 맥락과 함께 유지. 사료·향료 등의 조건부 결론을 일반 식품의 무조건적 결론으로 변환하지 않음 | 결론 분류의 근거 문장·적용 분야·대상이 확인됨. `ADI 없음`을 단일 의미로 취급하지 않음 |
| JECFA `13` | 조회 응답 원본, 조회 URL·시각·chemical ID를 저장하고, 필요한 항목의 세부 평가 출처·연도를 확보 | 검색 문자열만으로 출처를 대신하지 않음. 규격 자료와 평가 자료를 별도 근거로 보존 |
| EU `14` | 정책 ID·조건 ID 또는 원 JSON 경로를 남기고, 반복된 조건·식품군·단위·주석·예외를 각각 보존. 제외 노드는 사유 기록 | 원 노드마다 출력 또는 제외 사유가 대응됨. 반복 leaf가 `setdefault`로 조용히 사라지지 않음 |
| FDA `11`/통합 `09` | 물질 목록·용도·CFR·SCOGS·GRAS 통지의 자료 종류와 해당 기록 상태를 구분 | 자료의 목록 등재나 통지를 단일 `승인/안전` 값으로 변환하지 않음 |

EU QS 같은 코드는 우선 원 코드와 조건을 보존하고, 설명 문구는 해당 근거를 검토한 뒤 승인한다. 현재의 `양 제한 없음` 요약을 무조건적 허용처럼 공개하지 않는다. 미파싱 FDA 자료나 EU 신소재식품 상세는 해당 기능에 필요할 때 보완하고, 확보한 부분을 전체 DB라고 표현하지 않는다.

### 4단계 — 알레르겐의 관찰 사실과 추정을 분리한다

관련 코드: `10_build_allergen_map.py`.

현재 직접 포함 문자열을 먼저 검사하므로, 넓은 부분 일치가 구체적인 추정 규칙을 덮어쓸 수 있다. 이 경우 직접/추정 검사 순서만 뒤집어도 다른 정상 사례가 바뀔 수 있어 충분한 수정이 아니다.

규칙마다 ID·대상 토큰·일치 방식·제외 조건·근거를 두고, 토큰 전체에 대한 구체적인 규칙과 모호성 판정을 먼저 적용한다. 광범위한 부분 일치는 확인 후보 생성에 사용한다. 향, 복합원료, 선택 표현이 있는 이름은 제품별 표시나 배합 근거 없이 함유 확정으로 올리지 않는다.

서비스에 넘길 정보도 `제품 라벨에서 확인`, `원재료 유래 추정`, `정보 부족`처럼 근거를 구분한다. 이름으로 검출되지 않았다는 사실을 `알레르겐 없음`으로 바꾸지 않는다. 농도 등 별도 조건이 필요한 판단은 해당 값이 없으면 보류한다.

완료 기준: 알려진 오탐이 제거되고, 정상 직접 표시 사례도 유지되며, 미검출·추정·확정이 서로 바뀌지 않는다. 전수 규칙 점검과 별개로 실제 라벨 대조가 필요하다.

### 5단계 — 근거를 주장 단위로 검토하고 카드를 만든다

관련 코드: `09_build_evidence_candidates.py`, 수동 근거 병합.

한 후보 행 안에서도 ADI는 사람이 확인했고 EU 조건은 자동 생성됐을 수 있다. `사람 확인`이라는 행 라벨 하나로 두 정보를 모두 승인하면 안 된다.

근거 한 건마다 최소한 다음 정보를 갖추는 방안을 제안한다. 이는 논리적 요구사항이며 Supabase 테이블 설계를 확정한 것이 아니다.

- 어떤 물질에 대한 어떤 주장인지: 원료 ID, 주장 종류, 값 또는 원문, 단위, 대상·기준·사용조건.
- 어디서 왔는지: 기관, 원본 버전, 원 레코드 ID/위치, 평가서 링크, 적용 시점.
- 어떻게 연결하고 확인했는지: 매칭 근거, 검토 상태, 검토자, 확인일, 관련 코드·규칙 버전.

`자동 후보 → 검토 대기 → 승인/반려`를 주장별로 관리한다. 여러 기관의 평가가 다르면 병렬로 보존하고, 숫자가 있다는 이유나 최신 연도라는 이유만으로 하나를 정답으로 고르지 않는다. 수동 근거도 원문·적용 범위가 추적되지 않으면 해당 주장만 재검토한다.

카드는 승인된 주장만 조합해 생성한다. 역할 정보만 승인됐으면 역할만 보여줄 수 있다. 필드 하나가 미확인이라는 이유로 모든 성분 정보를 버릴 필요는 없다.

## 4. 재생성 흐름과 실행 우선순위

권장 흐름은 **원본 스냅샷 → 기관별 원 기록 → 원료·식별자 연결 후보 → 주장별 근거 → 사람 검토 → 공개 카드**다.

현재 `13_fetch_jecfa.py`가 `evidence_candidates.csv`에서 조회 대상을 읽고, `09`는 다시 JECFA 결과를 읽는다. 조회 대상 목록을 독립 산출물로 분리해 실행 순서를 명확히 한다. `16`도 통합 후보의 영문명을 받아 식별자를 붙이는 구조이므로, 최종 카드 생성 전에 동일성 검토 결과가 사용되도록 순서를 조정한다.

실행은 다음 순서가 합리적이다.

1. 스냅샷·회귀 사례를 만들고, 공란을 `제한 없음`으로 바꾸는 규칙과 미검토 근거의 공개 경로부터 막는다.
2. 원료 연결, EFSA 원 기록, 국내 상태, 알레르겐 규칙을 수정한다. 이들이 현재 카드의 핵심 오류를 직접 만든다.
3. EU·JECFA·FDA의 공개에 필요한 필드와 출처를 복원하고 주장별 검토 상태를 붙인다.
4. 자주 등장하며 범위가 명확한 성분군부터 작은 검토 묶음을 완성한다. 수동 근거가 있는 항목도 출처·자동 보강 필드의 검토 범위를 확인한다.
5. 검증된 묶음으로 서비스 데이터 계약을 검토하고 Supabase 스키마를 확정한다. 그 뒤 전체 범위를 점진적으로 확대한다.

5,940개 후보를 한 번에 사람이 전부 검토할 필요는 없다. 빈도와 오연결 영향, 공개 필요성을 함께 기준으로 삼는다. 드물더라도 사용자 제한·알레르겐과 관련된 미확인 항목은 자동 통과시키지 않는다.

## 5. 수정 완료를 판단할 기준

| 검사 | 통과 조건 |
|---|---|
| 계보·재현성 | 입력 버전·코드 버전·출력과 제외 사유를 추적 가능 |
| 원 기록 보존 | EFSA 평가와 EU 조건의 각 원 기록을 출력 또는 사유 있는 제외에 대응 가능 |
| 동일성 | 공개 연결에 미해결 다중 후보·포괄명 강제 축소 없음 |
| 국내 상태 | 금지·제한·공란을 무제한 허용으로 바꾼 알려진 회귀 사례 0건 |
| 알레르겐 | 향·복합·모호 토큰을 함유 확정으로 승격한 알려진 회귀 사례 0건; 정상 사례도 유지 |
| 주장별 승인 | 공개되는 모든 주장에 원 출처·검토 상태·범위가 존재 |
| 변경 검토 | 승인 근거의 입력 버전·연결·값·조건이 달라지면 재검토 대상으로 표시 |

알려진 회귀 사례 0건은 전체 오류율 0%를 뜻하지 않는다. 새 미확인 토큰, 기관 간 평가 차이, 실제 라벨과 공공DB의 시점 차이를 계속 검토할 수 있어야 한다.

## 6. 작성자 구분

Codex 작성으로 확인된 `docs/10`, `docs/11`, `docs/13`에 작성자를 표시했다. `data/raw/README.md`에는 이 대화에서 수행한 작성·개정을 표시했다. `docs/10`·`11`은 기존 인수인계 기록, `docs/13`은 Codex의 파일 생성 기록으로 확인했다. 이 문서도 Codex 작성이다.

다른 문서는 파일명에 Codex가 들어가거나 Codex 결과를 인용했다는 이유만으로 작성자를 변경하지 않았다. 특히 `data/raw/codex/`의 Codex는 식품규격위원회 자료를 뜻하므로 AI 작성자 판별 근거가 아니다. 앞으로 공동 수정 시 원 작성자는 유지하고 수정자·날짜·변경 범위를 별도 기록한다.
