# 04. 성분 사전 구축 계획

작성일: 2026-09-14 · 근거: `data/prepared/products.csv` 전수 실측 (제품 168.7만 건 · 원재료 등장 1,080만 회)

> 제품 DB(168.7만 건)는 **"이 제품에 뭐가 들었나"** 를 답한다. 이 문서는 **"그게 뭔가"** 를 답하는 층을 만드는 계획이다. 제품 DB는 329MB이고 이 사전은 수 MB지만, **제품의 실력은 이쪽에서 나온다.**

## 1. 목표 — 제품 완전 판독 99.9%

### 1-1. 등장 기준과 제품 기준은 전혀 다르다

제품당 원재료가 평균 **6.4개**다. **하나만 몰라도 그 제품은 완전 판독이 아니다.**

| 사전 보유 | 등장 기준 커버리지 | **제품 완전 판독** |
|---:|---|---|
| 3,017종 | 95% | **81.8%** |
| 12,784종 | 99% | **96.1%** |
| 51,745종 | 99.9% | **99.5%** |
| **58,960종 (전량)** | 100% | **100%** |

**목표는 제품 완전 판독 99.9%다.** 상위 몇백 종으로는 상업 서비스가 안 된다.

### 1-2. 정규화로는 줄지 않는다 (실측)

공백·괄호·숫자·원산지 꼬리를 제거해도 **62,542종 → 58,955종, 6% 감소**에 그친다. 꼬리가 표기 변형이 아니라 **실재하는 다른 재료**이기 때문이다.

- 1회만 등장하는 표기 **25,686종 (44%)**
- 5회 이하 **42,565종 (72%)**
- 실제 예: `석창포뿌리줄기`, `신양벚나무열매분말`, `홍미삼`, `발효녹차` — 오타가 아니다

### 1-3. 🔴 그래도 표기 변형은 반드시 처리해야 한다

머릿속 이름으로 찾으면 **아예 안 걸린다.**

| 우리가 아는 이름 | 실제 표기 | 그대로 찾으면 |
|---|---|---|
| 알룰로스 | **알룰로오스** 4,913회 (단일 표기) | **0건** |
| 카놀라유 | `채종유(유채유 또는 카놀라유)` 12,848 · 띄어쓰기 뺀 것 5,078 … **35종** | 1건 |
| 말티톨 | `말티톨시럽` 1,503 · `D-말티톨` 843 · `말티톨액` 381 … **20종** | 30건 |
| 스테비아 | `효소처리스테비아` 38,848 · `스테비올배당체` 4,789 … **126종** | — |

## 2. 핵심 인식 — 등록과 근거 카드는 다른 일이다

99.9%를 채우는 데 6만 종의 평가서가 필요한 게 아니다. **토큰마다 필요한 깊이가 다르다.**

| 층 | 대상 | 필요한 것 | 규모 | 방식 |
|---|---|---|---|---|
| **A. 식별** | **전량** | 표준명·범주만 ("이게 무엇인가") | 58,960종 | **자동 + 검수** |
| **B. 판정** | 저탄고지 관련 | 모드 기본값 (피해요/알려만줘요 2단계) | 수백 종 | 사람 |
| **C. 근거 카드** | 쟁점 성분 | 각국 기준·출처·혼동 정정 | 수십 종 | 사람 (가장 무겁다) |

**99.9%가 필요한 것은 A층뿐이다.** `석창포뿌리줄기`는 "약용식물 원물 · 저탄고지 무관"이면 충분하고 EFSA 평가서를 읽을 필요가 없다.

## 3. 출처

⚠️ **계획서의 기존 서술이 틀렸다.** "식약처 식품첨가물 정보 API(`FoodAdtvInfoService01`)로 성분 마스터를 자동 수집한다"고 적혀 있었으나, **실호출 결과 그 API는 식품 유형별 기준·규격**(예: "과자 – 세균수 – 1g당 10,000 이하", 32,746건)이며 **용도 필드가 없다.** 공공데이터포털 `15058807`도 같은 엔드포인트다. **성분의 용도를 주는 식약처 오픈API는 사실상 없다.**

| 채울 항목 | 출처 | 형태 | 자동화 |
|---|---|---|---|
| 표기 변형·빈도 | **우리 제품 DB** (등장 1,080만) | 로컬 | ✅ 자동 |
| 원물 식별 (대표명·이명·학명·분류) | **`I2520` 식품원재료코드 43,612건** · `I1020` 식품원재료 정보 24,875건 | 오픈API | ✅ 자동 |
| 용도 (감미료·증점제 등) | 「식품첨가물의 기준 및 규격」 고시 | 고시 문서 | 반자동 |

| 각국 기준·평가 결론 | EFSA · JECFA · IARC · FDA GRAS | 문서(PDF) | ❌ 수작업 |

**용도명 병기는 공공DB에 0.2%뿐이다.** 품목제조보고는 라벨 문구가 아니라 사용한 원재료를 적은 것이라서다. 라벨 촬영 경로에서는 `감미료(수크랄로스)` 형태로 더 자주 잡히므로 보조 신호로 쓴다.

## 4. 구축 5단계

### 1단계 — 공공 원재료 마스터 자동 대조 · 1h ✅ 완료

**효율이 가장 높은 단계다.** `석창포뿌리줄기` 같은 원물 대부분이 `I2520`(43,612건)에 이미 들어 있다. 문자열 대조만으로 수만 종이 자동 분류된다.

```
우리 토큰 58,960종  ×  I2520 대표명·이명 43,612건  →  자동 매칭
                     ×  I1020 원재료 정보 24,875건  →  사용조건 보강
```

⚠️ **선행 조건: 두 서비스 활용신청** (§6)

### 2단계 — 파생어 규칙 분해 · 2h

`신양벚나무열매분말` → `신양벚나무열매`(원물) + `분말`(형태)

- 접두 일치: 기반어로 시작하는 파생어
- 접미사 사전: 분말·가루·농축액·추출물·시럽·액·유·가공품·조제품·페이스트·건조 등
- 괄호 안 동의어 자동 수집: `콩기름(대두유)`, `검정깨(흑임자)` — **데이터가 동의어를 직접 알려준다**

기반 사전이 3,000종일 때 꼬리의 25.8%가 해석됐다. **1단계로 기반이 4만 종대로 커지면 해석률이 크게 올라간다.**

### 3단계 — LLM 일괄 분류 · 4h (+ API 비용)

1·2단계에서 남은 것만 배치로 넘긴다.

| | |
|---|---|
| 묻는 것 | **"이 토큰은 무엇이고 어느 범주인가"** — 원물 / 가공품 / 첨가물 / 복합원재료 / 불명 |
| 묻지 않는 것 | **판정.** 저탄고지에 맞는지는 시키지 않는다 (계획서 §설계 원칙 1) |
| 처리 | 100개씩 배치. Gemini Flash 기준 비용은 수천 원 수준 |
| 출력 | 그대로 쓰지 않고 **4단계 검수 대상만 골라낸다** |

### 4단계 — 사람 검수 · 8h

검수 대상은 전체가 아니라 **당류·전분·감미료·유지로 분류된 것**이다. 1~3단계를 거치면 수백 개로 줄어든다. **여기서 전공(식품공학)이 쓰인다.**

| 확인할 것 | 예 |
|---|---|
| 같은 것의 다른 표기 | `알룰로오스`=`알룰로스`, `백설탕`=`설탕`, `채종유`=`카놀라유` |
| **다른 것인데 비슷한 이름** | `말티톨` vs `말토덱스트린` — **절대 합치지 않는다** |
| 불투명 토큰 | `복합조미식품`·`혼합제제`·`기타가공품`·`소스` → **확인 불가**로 분류 |
| 모드 기본값 | B층 — 성분별 피해요/알려만줘요 초안을 제시하고 사용자가 확인·수정해 확정. 표시 위치로 설정을 바꾸지 않음 |

### 5단계 — 운영 중 자동 확장 · 지속

```
라벨·신제품에서 새 토큰 발견 → ingredient_feedback 큐에 적재
                              → 월 1회 재적재 때 1~3단계 재실행
                              → 저탄고지 관련만 사람 검수
```

**사전은 시간이 갈수록 커지고 미등록률은 계속 떨어진다.** 이것이 계획서가 말한 성장 루프의 실체다.

### 6단계 — 근거 카드 (C층) · 28h

`08_성분_근거자료집`. 전체에서 가장 무겁다.

| 대상 | 시간 | 왜 |
|---|---:|---|
| 식품원료 (설탕·밀가루·유지류) | 8h | 허용기준 개념이 없어 영양성분·WHO 권고만 |
| 감미료 10종 | 20h | 기관마다 결론이 갈려 EFSA·JECFA·IARC·FDA를 직접 확인 |

**베타 시작 조건은 A·B층 전량 + C층의 식품원료·감미료까지다.**

## 5. 100%는 불가능하다 — 안전판이 함께 간다

신제품에 새 원료가 계속 들어온다. **미등록 토큰이 하나라도 있으면 "판단 보류 — 확인 불가 N개"로 표시한다.**

이것은 실패가 아니라 정직한 답이다. 99.9%를 채우는 노력과, 못 채운 0.1%를 숨기지 않는 설계는 **둘 다 필요하다.**
