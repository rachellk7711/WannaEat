# 02. 법무 · 표현 설계

> **이 문서는 법률 자문이 아니다.** 1인 개인이 서비스를 출시할 때 실무적으로 리스크를 낮추는 설계 지침이다.
> 유료화 이후 이용자가 늘거나 언론·업계의 주목을 받는 단계가 되면 변호사 검토를 별도로 받아야 한다.

## 1. 가장 큰 리스크 — 식품표시광고법 제8조

### 조문의 위험한 지점

**「식품 등의 표시·광고에 관한 법률」 제8조(부당한 표시 또는 광고행위의 금지)** 의 금지 유형에 다음이 명시되어 있다.

> **다른 업체나 다른 업체의 제품을 비방하는 표시 또는 광고**
>
> 객관적인 근거 없이 자기 또는 자기의 식품 등을 다른 영업자나 다른 영업자의 식품 등과 부당하게 비교하는 표시 또는 광고

**핵심: 조문은 "누구든지"로 시작한다.** 식품 제조·판매업자에게만 적용되는 것이 아니다. 우리가 식품을 팔지 않아도, 특정 제품을 비방하는 표시·광고를 하면 적용 대상이 될 수 있다.

같은 조문은 질병 예방·치료 효능 표방, 의약품 오인, 건강기능식품 오인, 거짓·과장, 소비자 기만도 함께 금지한다. **우리 서비스는 이 다섯 가지도 전부 건드리지 않는다.**

### 함께 고려할 다른 근거

| 법률 | 위험 상황 |
|---|---|
| 형법 (명예훼손·업무방해) | 특정 제품·제조사를 지목해 부정적으로 단정 |
| 부정경쟁방지법 | 경쟁 목적의 비방 |
| 정보통신망법 | 온라인상 명예훼손 |

## 2. 방어 구조 — "우리는 판단하지 않는다"

리스크를 없애는 방법은 표현을 순화하는 것이 아니라 **판정의 주체를 사용자로 옮기는 것**이다.

```
❌  우리가 제품을 평가한다          →  비방 소지
✅  사용자가 설정한 기준과 대조한다  →  사실 확인
```

같은 정보를 전달하면서 법적 성격이 달라진다.

| 우리가 하는 일 | 우리가 하지 않는 일 |
|---|---|
| 원재료명에 어떤 성분이 있는지 **표시** | 그 성분이 나쁘다고 **평가** |
| 사용자가 제외 설정한 성분과 **대조** | 제품 등급을 **부여** |
| 성분의 용도(감미료·보존료 등)를 **사실로 안내** | 건강 영향을 **주장** |
| 정부 공개 데이터를 **인용** | 자체 판단을 **단정** |

### 이 구조가 성립하기 위한 3가지 필수 요건

1. **사용자가 기준을 직접 설정하거나 선택해야 한다.** 기본값을 제공하더라도 그것이 "우리 권고"가 아니라 "저탄고지 식단에서 통용되는 분류"임을 밝히고 수정 가능하게 한다
2. **모든 결과 표기에 "내 기준" 문구가 붙어 있어야 한다.** 문구 없이 색상·아이콘만 남으면 제품 등급으로 읽힌다
3. **원재료명의 출처를 표시해야 한다.** 식약처 공개 데이터인지 사용자가 올린 이미지인지 화면에 명시

## 3. 금지어 / 대체어 사전

UI, 상세페이지, 커뮤니티 게시글, 고객 응대, **자동 생성 콘텐츠 전체**에 적용한다.

### 3-1. 절대 사용 금지

| 금지 표현 | 이유 |
|---|---|
| 해롭다 / 위험하다 / 나쁘다 | 건강 영향 단정 |
| 발암 / 독성 / 유해 | 위험성 단정, 객관적 근거 요구됨 |
| 먹지 마세요 / 피하세요 | 지시·권고 |
| 최악 / 쓰레기 / 불량 | 비방 |
| 1등 / 최고 / 가장 안전한 | 부당 비교 |
| ○○보다 낫다 (제품명 지목) | 부당 비교 |
| 다이어트에 효과 / 살이 빠진다 | 효능 표방 |
| 당뇨에 좋다 / 염증을 줄인다 | 질병 관련 효능 표방 |
| 디톡스 / 해독 | 의학적 근거 없는 효능 표방 |

### 3-2. 대체 표현

| 이렇게 쓰지 말고 | 이렇게 쓴다 |
|---|---|
| "이 제품은 강력반대" | **"회원님 기준에 맞지 않는 원재료 3건"** |
| "몸에 나쁜 첨가물 포함" | **"회원님이 제외 설정한 성분: 말토덱스트린, 정제당"** |
| "설탕이 들어있어 위험" | **"당류 항목 해당: 설탕"** |
| "이 제품 추천" | **"회원님 기준과 일치"** |
| "안전한 제품" | **"기준 불일치 항목 없음"** |
| "첨가물이 많음" | **"등록된 첨가물 5종 확인"** |
| "저탄고지에 안 좋음" | **"저탄고지 기준에서 일반적으로 제외되는 성분"** |

### 3-3. 성분 설명 시의 경계선

| 안전 (사실 진술) | 위험 (평가·단정) |
|---|---|
| "말티톨은 당알코올류 감미료입니다" | "말티톨은 혈당을 올려서 안 좋습니다" |
| "저탄고지 식단에서 의견이 갈리는 성분입니다" | "저탄고지에 부적합한 성분입니다" |
| "식약처 식품첨가물로 등록된 감미료입니다" | "인공 감미료라 피해야 합니다" |
| "혈당지수에 관해 논쟁이 있습니다" | "혈당을 급격히 올립니다" |

**원칙: 성분 설명은 "무엇인가"까지만. "어떤 영향을 주는가"는 쓰지 않는다.**

불가피하게 필요하면 *"○○ 식단 커뮤니티에서는 일반적으로 △△로 분류합니다"* 처럼 **출처를 커뮤니티 통념으로 돌리고 단정하지 않는다.**

## 4. 화면 문구 (완성 텍스트)

### 4-1. 결과 화면 상단 고정 문구

```
회원님이 설정한 [저탄고지] 기준과 대조한 결과입니다.
제품에 대한 평가나 등급이 아닙니다.
```

### 4-2. 결과 라벨 — 함량이 아니라 "표시 위치"

> **⚠️ 2026-09-14 갱신.** 초안은 "많이 포함 / 소량 포함"처럼 **함량**으로 표기했으나, **표시 위치**로 바꿨다.
> **「식품등의 표시기준」에 예외가 있기 때문이다.** 원재료는 많이 사용한 순서로 표시하는 것이 원칙이지만, **중량 2% 미만은 순서를 따르지 않아도 되고**, **중량 5% 미만 복합원재료는 하위 원료를 밝히지 않아도 된다.** 원재료가 3개뿐이면 마지막도 25%일 수 있다.
> **→ 표시 위치로 함량을 단정하면 사실과 다른 주장이 된다.**

⚠️ **2026-09-14 재정정.** 앞선 표는 **제품 단위 결론**과 **성분 단위 위치**를 한 칸에 섞어 놓아 *"무엇이 발견되지 않았다는 것인가"* 로 읽혔다. 두 층위를 분리한다.

### ① 제품 단위 — 결론 한 줄

| 화면 표기 | 조건 | 보조 문구 |
|---|---|---|
| **기준 불일치 · N개** | 피해요로 설정한 성분이 하나 이상 발견 | 피해요로 설정한 성분이 발견됐어요 |
| **기준 내** | 피해요로 설정한 성분이 발견되지 않음 | 피해요로 설정한 성분을 찾지 못했어요. 알려만줘요 항목은 별도로 안내해요 |
| **판단 보류** | 판독 실패로 결론을 낼 수 없음 | 원재료 표시를 충분히 읽지 못했습니다. 다시 촬영해 주세요 |

### ② 성분 단위 — 무엇이 어디에 있나

| 성분 | 표시 위치 | 내 기준 | 판정 |
|---|---|---|---|
| 설탕 | 앞쪽 | 피해요 | 불일치 |
| 밀가루 | 중간 | 피해요 | 불일치 |
| 정제소금 | 뒤쪽 | 알려만줘요 | 발견 사실 안내 (불일치에 포함하지 않음) |

**위치는 성분의 속성이지 제품의 결론이 아니다.** 2026-09-18 사용자 결정에 따라 `피해요 / 알려만줘요` 2단계 설정과 발견 여부로 성분별 처리를 결정하고, 그 결과를 모아 ①의 결론을 만든다.

| 표시 위치 | 피해요 | 알려만줘요 |
|---|---|---|
| 앞쪽 | 불일치 | 발견 사실 안내 |
| 중간 | 불일치 | 발견 사실 안내 |
| 뒤쪽 | 불일치 | 발견 사실 안내 |

`알려만줘요` 항목은 불일치 개수에 포함하지 않는다. 선택하지 않은 원재료는 개인 기준 대조 대상에서 제외하며 세 번째 설정 버튼으로 표시하지 않는다. 읽지 못했거나 하위 원료를 확인할 수 없는 항목은 두 설정 모두 `확인 불가`로 별도 안내한다.

### ③ 판독 상태 — 항상 별도 줄

`기준 내`로 끝나더라도 **확인 불가가 있으면 반드시 함께 표시한다.** 라벨에 적히지 않은 것을 우리가 보증할 수는 없다.

```
기준 내
피해요로 설정한 성분을 찾지 못했어요
⚠ 단, 확인 불가 1개 — 복합조미식품 (하위 원료가 표시되지 않음)
```

**설정 화면에서 두 표기의 뜻을 밝힌다:** `피해요` — *"이 원재료가 표시된 제품을 피하고 싶어요."* / `알려만줘요` — *"이 원재료가 표시되면 알려주세요."* 표시 위치로 양이나 허용 여부를 추정하지 않는다.

**금지 표기:**

| ❌ | 이유 |
|---|---|
| "강력반대 / 비추 / 감안 수용 / 강추" | **권고형 어휘.** 우리가 판정하는 것이 된다 |
| "부적합" · "추천" · "위험" · "안전" | 제품 등급으로 읽힌다 |
| 0~100점 게이지 | 등급 부여 |
| **"많이 포함" · "소량 포함" · "○○ 없음"** | **함량을 측정했다는 주장**이 된다. 표시 위치로는 함량을 알 수 없다 |

### 4-2-1. 판독 상태는 결과와 함께 표시한다 (필수)

**모르는 것을 "발견되지 않음"으로 합치지 않는다.** 이것이 사용자에게 가장 위험한 오류다.

```
내 기준 대조   피해요로 설정한 성분 발견되지 않음
판독 상태      ⚠ 확인 불가 3개 — 복합조미식품, 혼합제제, 기타가공품
               하위 원료가 라벨에 표시되지 않아 내용을 알 수 없습니다
```

| 확인 불가 유형 | 문구 |
|---|---|
| 하위 원료 미표시 복합원재료 (**제품의 34%**) | "하위 원료가 라벨에 표시되지 않아 내용을 알 수 없습니다" |
| 사전에 없는 미등록 성분 | "아직 등록되지 않은 원재료입니다: ○○○" |
| 판독 실패 | "읽지 못한 부분이 있습니다. 다시 촬영해 주세요" |

**경로별 제약:** C002·C006은 `RAWMTRL_ORDNO`로 정렬해 표시 순서를 복원한다 (2026-09-11 검증). **ORDNO가 없는 C003(건기식)과 순서 검증 전인 수입식품은 위치를 표시하지 않고 포함 여부만** 보여준다. 원재료 개수와 순서 개수가 맞지 않는 제품(1.4%)은 "원재료 정보가 불완전할 수 있습니다"를 함께 표시한다.

## 4-A. 성분 카드 — 근거 제공의 표현 규칙

> **이 절은 `02_법무` 초안 이후에 확정되었다.** 상세는 `계획서.md` §성분 카드 형식 / §출처 등급 참조.

### 핵심 원칙 — 논쟁을 서술하지 않는다

**각국 허용기준을 나열하면 논쟁이 스스로 드러난다.** 우리가 *"논쟁이 있습니다"*, *"~하는 것도 합리적입니다"* 라고 쓰는 순간 그것은 우리 의견이 된다.

가장 선명한 근거: **수크랄로스는 주류 의학 채널은 긍정, 키토 커뮤니티는 회피 — 정반대다.** 같은 성분인데 출처에 따라 판정이 뒤집힌다. "정답"이 없으므로 **기준만 나열하고 판단은 사용자에게 남긴다.**

### 카드 형식 — 기본 2줄, 최대 3줄

```
성분명 (통용명)                          [피해요] [알려만줘요]
1줄: 원료·용도 · 특징
2줄: 기준 (차이가 있을 때만 나열)   [기관 배지]        [자세히 ▾]
3줄: ※ 혼동 정정 — 필요한 경우만
```

**모든 기관을 나열하지 않는다.** 대부분의 성분은 국내·미국·유럽이 같은 결론이다. **기준이 갈리는 지점만** 표시한다.

### 🔴 출처 등급 — 기사는 쓰지 않는다

**모든 줄에 출처를 붙인다. 출처가 없는 줄은 쓰지 않는다.**

| 등급 | 종류 | 예 |
|---|---|---|
| **S** | 법령·고시 원문 | 식품첨가물공전, EU Reg. 1333/2008, 21 CFR |
| **A** | 규제기관 공식 평가서 | EFSA Journal(DOI), JECFA, IARC Monographs, FDA GRAS |
| **B** | 규제기관 보도자료 | 식약처 보도자료 |
| **C** | 정부 출연 연구기관 | 식품의약품안전평가원 |
| **D** | 체계적 문헌고찰 | ⚠️ A급이 없을 때만 |
| ❌ | **개별 논문 단독** | **체리피킹 = 우리 의견이 된다** |
| ❌ | 단일 동물실험 · in vitro | 인체 적용에 큰 간극 |
| ❌ | 신문·잡지 기사 · 블로그 · 위키 | 2차 전달, 검증 불가 |
| ❌ | 산업계 후원 연구소 · 옹호단체 | 이해관계 |
| ❌ | 커뮤니티 발화 | 규제 정보가 아니다 |

**개별 논문 단독 인용을 금지하는 이유:** 논문 하나를 고르는 것 자체가 우리 의견이다. 반대 결론의 문헌도 존재하기 때문이다. **규제기관 평가서는 그 기관이 문헌 전체를 검토한 결과이므로 체리피킹이 구조적으로 불가능하다.**

### 출처 선택 사다리

```
1. 그 기준을 정한 기관의 법령·고시 원문        ← 최선
2. 그 기관의 공식 평가서
3. 그 기관의 보도자료·안내
4. 다른 기관의 평가서
5. 정부 출연 연구기관 보고서
6. 체계적 문헌고찰 (규제 평가가 아예 없을 때만)
   ──── 여기까지. 아래는 쓰지 않는다 ────
```

**1~3단계를 못 찾으면 그 줄을 비워두는 것이 4단계 이하를 억지로 쓰는 것보다 낫다.**

### ⚠️ 규제기관과 커뮤니티가 정반대일 때 (MSG 문제)

| 잘못된 처리 | 이유 |
|---|---|
| "MSG는 유해합니다" | 규제기관 평가와 배치. **근거 없고 법적 위험** |
| "MSG는 안전합니다" | 회피하려는 사용자에게 쓸모없다. 우리가 판단을 대신함 |
| **"인공 합성조미료"** | **사실과 다르다** — MSG는 사탕수수 등을 **발효**해 생산한다. 그리고 부정적 프레이밍이다 |

**해법: 회피 이유를 갈래로 분해하되, 화면에는 `특징` 한 줄로만 압축한다.**

| | 회피 이유 | 우리가 지지 가능? |
|---|---|---|
| ⓐ | 유해성 우려 | ❌ 규제기관 평가와 배치 |
| ⓑ | **초가공식품의 지표** | ✅ **과학 논쟁과 무관하게 합리적** |
| ⓒ | 개인 감수성 | ✅ 본인 경험은 반박 대상이 아니다 |

**→ 축 라벨링에서 유해성 함의를 제거한다:** `"위험 성분"` ❌ → **`"초가공 지표 성분"`** ✅

### "건강 영향"은 못 쓰지만 "섭취 권고량"은 쓸 수 있다

| ❌ 못 씀 (가치 판단) | ✅ 쓸 수 있음 (사실·공적 권고) |
|---|---|
| "설탕은 간 건강을 해친다" | **WHO 권고: 자유당 총열량의 10% 미만** (2015) |
| "글루텐은 염증을 유발한다" | **"글루텐 함유"** + **알레르기 유발물질 표시 대상**(법정 22종) |

**원칙: 건강 결과를 서술하지 말고, 공적 기관이 정한 숫자를 인용한다.**

### 혼동 정정은 허용된다

```
카라기난 (식품용)          → IARC Group 3(발암성 미분류). JECFA 안전성 검증
분해 카라기난 (poligeenan) → 장 염증·세포독성 보고. 식품용 사용 금지
```

*"분해 카라기난과 다른 물질"* 은 **의견이 아니라 사실 정정**이므로 `특징`에 쓸 수 있다.

### 출처 원문 로컬 보관 — `docs/refs/`

URL만 두면 안 된다. **규제 문서는 개정되고 식약처 보도자료 URL은 바뀐다.**

`docs/refs/_index.md` 대장에 **성분·기관·문서명·발행일·접근일·DOI·URL·로컬파일명** 을 기록한다.
**사용자에게는 원문 링크만 제공하고 우리 PDF를 배포하지 않는다.**

## 5. 개인정보 — 국외이전이 핵심 쟁점

### 5-0. ⚠️ 먼저 — Gemini 무료 티어 약관이 우리 서비스와 충돌한다

[Gemini API 추가 약관](https://ai.google.dev/gemini-api/terms)은 **무료 할당량** 사용에 대해 다음을 명시한다.

> - Google은 제출된 콘텐츠와 응답을 **제품 개선 및 ML 학습에 사용**한다
> - **인간 검토자가 입력과 출력을 읽고 주석을 달 수 있다**
> - **민감정보·기밀정보·개인정보를 무료 서비스에 제출하지 말 것**

마지막 항목이 핵심이다. **Google 스스로 개인정보를 넣지 말라고 경고하고 있다.**

우리 서비스는 사용자가 올린 이미지에 실내 배경·인물·영수증·배송지가 함께 찍힐 수 있다. 이 상태로 무료 티어를 쓰는 것은 **약관 위반이자 개인정보 보호 관점에서 방어하기 어려운 구조**다.

**대응 (2026-09-14 확정)**

| # | 조치 | 시점 |
|---|---|---|
| 1 | **처음부터 유료 티어를 쓴다** | 베타 시작 시점부터. 무료 티어는 쓰지 않는다 |
| 2 | **전송 전 확인 화면을 건너뛸 수 없게 한다** (크롭은 선택) | 개발 시 필수 구현 |
| 3 | **이용약관·베타 모집 대상을 18세 이상으로** | 약관은 18세 미만을 대상으로 하거나 접근 가능성이 있는 서비스에 API 사용을 제한한다 |

⚠️ **유료 티어라고 모든 보관이 사라지는 것은 아니다.** 학습 사용은 배제되지만 남용 방지 목적의 제한적 로그·임시 캐시는 남을 수 있다. *"우리 서버에 저장하지 않는다"* 와 *"모든 업체가 즉시 삭제한다"* 는 다른 말이므로 고지 문안에서 구분한다.

> 참고: 잘라내기는 정확도 향상에도 효과적이라는 점이 `00_사전검증_노트.md` V1에서 확인됐다. 다만 **크롭 강제는 법적 의무가 아니라 우리가 택한 보호 장치**다. 핵심은 **원본 자동 업로드를 막고 사용자가 전송 범위를 확인하게 하는 것**이다.

### 5-1. 국외이전이 왜 문제가 되는가

Gemini API는 Google이 제공하므로 **이미지가 국외로 이전된다.**

「개인정보 보호법」 제28조의8은 개인정보의 국외 제공·처리위탁·보관을 **원칙적으로 금지**하고 다음 예외를 둔다.

- 정보주체가 **별도로 동의**한 경우
- 정보주체와의 **계약 체결·이행을 위해 처리위탁·보관이 필요**한 경우로서, 국외이전 동의 시 고지해야 하는 사항을 **개인정보 처리방침에 공개**하거나 이용자에게 알린 경우
- 이전받는 자가 보호위원회가 정한 인증을 받은 경우
- 이전 대상 국가·국제기구가 보호위원회로부터 보호수준 인정을 받은 경우

**⚠️ 근거를 먼저 선택한다 (미확정).** "동의"와 "계약 이행을 위한 처리위탁 + 처리방침 공개"는 **서로 다른 근거**다. 둘 다 하면 안전해 보이지만, 매 업로드마다 중복 동의를 받는 구조는 실제 처리 목적과 맞지 않을 수 있다. **실제 이전 목적(라벨 판독 위탁)과 수탁 관계를 정리한 뒤 근거를 고른다.**

또한 **모델 개선 목적은 처리위탁으로 자동 포괄되지 않는다.** 유료 티어를 쓰면 학습 사용이 배제되므로 이 문제는 줄지만, 고지 문안에서 "서비스 제공을 위한 처리"와 "개선 목적 처리"를 구분해 적는다.

### 5-2. ⚠️ 장바구니 캡처의 개인정보 위험

이것이 이 서비스에서 가장 실질적인 개인정보 리스크다.

**쇼핑몰 장바구니 화면에는 다음이 함께 찍힐 수 있다:**
- 계정 이름 / 아이디
- 배송지 주소
- 주문번호 · 결제 정보 일부
- 최근 본 상품 등 행태 정보

이 이미지를 그대로 Google로 보내면 **개인정보를 국외로 이전하는 것**이 된다.

**설계로 막는다:**

| 조치 | 내용 | 필수도 |
|---|---|---|
| **전송 전 확인 화면** | 업로드 직후 **무엇이 전송되는지 보여주는 화면**을 띄운다. 건너뛸 수 없다 | **필수** |
| 잘라내기 | 확인 화면에서 제공. **원재료만 찍힌 사진이면 전체 영역 그대로 허용** | 선택 |
| 안내 문구 | "이름·주소·주문번호가 보이지 않는지 확인해 주세요" 를 확인 화면에 상시 표시 | **필수** |
| 서버 미보관 | 이미지는 저장하지 않고 통과만 시킨다 | **필수** |
| 추출 범위 제한 | 프롬프트에서 **제품명·원재료만 추출**하도록 명시하고 인명·주소·연락처는 추출하지 않도록 지시 | **필수** |
| 자동 마스킹 | 클라이언트에서 개인정보 패턴 영역을 흐리게 처리 | 권장 (2차) |

> **프롬프트 수준의 방어는 완전하지 않다.** 이미지 자체가 이미 전송되기 때문이다.
> 따라서 **원본 자동 업로드를 막고 전송 범위를 사용자가 확인하게 하는 것**이 실질적인 방어선이다. 잘라냈다고 개인정보가 반드시 사라지는 것도 아니다.
> ※ 장바구니 일괄 확인은 **MVP에서 제외**됐으므로 이 위험은 당분간 줄어든다. 다만 사용자가 장바구니 화면을 올릴 수는 있으므로 확인 화면은 그대로 둔다.

### 5-3. 데이터 취급 원칙

| 데이터 | 보관 여부 | 비고 |
|---|---|---|
| 업로드 이미지 | **저장하지 않음** | 클라이언트 → 서버 함수 → AI API 통과 후 폐기 |
| 추출된 원재료명 텍스트 | 저장 (별도 동의) | 룰셋 개선용. 개인식별정보 없음 |
| 분석 이력 | 저장 | 회원 본인만 조회 (RLS 적용) |
| 회원 계정 정보 | 저장 | 최소 수집 — 이메일만 |

### 5-4. 인프라 리전 — 국외이전을 줄이는 기술적 조치

| 구성요소 | 권고 | 이유 |
|---|---|---|
| **Supabase 리전** | **서울 (ap-northeast-2)** | 회원정보·분석이력이 국내에 머문다. 국외이전 대상에서 제외 |
| **호스팅** | Cloudflare Pages (정적 자산) | 개인정보를 다루지 않는다 |
| **API** | Supabase Edge Functions | 리전 설정 확인 필요 |
| Gemini API | 국외 불가피 | 고지 + 근거 선택 (§5-1) |

**프로젝트 생성 시 Supabase 리전을 반드시 서울로 지정할 것.** 나중에 바꾸려면 마이그레이션이 필요하다.

⚠️ **서울 리전이 "국외이전 대상에서 완전히 제외"를 보증하지는 않는다.** Supabase도 선택 리전의 저장·주된 처리를 규정하면서 예외와 하위 처리자를 둔다. 인증 메일·지원·로그처럼 실제로 쓰는 경로를 확인해 처리방침에 반영한다.

## 6. 정확도 한계 고지

이 서비스는 여러 지점에서 틀릴 수 있고, 전부 미리 알려야 한다.

| 오류 지점 | 원인 | 고지 문안 |
|---|---|---|
| 원재료명 인식 오류 | OCR 실패, 흐릿한 이미지 | "자동 인식 결과로 실제 표기와 다를 수 있습니다" |
| 제품 매칭 오류 | 동명 제품, 상품명 불일치 | "조회된 제품이 회원님이 구매하려는 제품과 다를 수 있습니다. 제조사와 제품명을 확인해 주세요" |
| 공개 데이터 시점 차이 | 제조사의 원재료 변경 미반영 | "식약처 공개 데이터 기준이며, 제조사가 원재료를 변경한 경우 최신 정보와 다를 수 있습니다" |
| 성분 분류 누락 | 미등록 성분 | "분류 기준에 등록되지 않은 성분은 '참고 항목'으로 표시됩니다" |

**알레르기 관련 고지는 별도로, 더 강하게 한다.**

```
본 서비스는 식품 알레르기 판별 용도로 사용할 수 없습니다.
알레르기 유발물질 확인은 반드시 제품 실물의 표시사항을 통해 하십시오.
```

> **1차 버전에서 알레르기 모드를 넣지 않는 이유가 여기 있다.** 틀렸을 때의 결과가 건강 피해로 직결된다.

## 7. 사업자등록과 수익 — 2026-09-18 정정

**이 서비스는 무료로만 운영한다. 구독·인앱 결제·광고를 넣지 않는다.**
운영자가 사업자가 아니고, 앱인토스에서 유료 상품 판매와 인앱 광고는 **모두 사업자 등록을 요구**하기 때문이다.
따라서 아래 절차는 지금 적용 대상이 아니며, 사업자 등록을 하기로 결정할 때 다시 꺼내 쓴다.

### 7-1. 기준은 첫 매출이 아니라 사업 개시일

부가가치세법은 **사업 개시일부터 20일 이내** 등록하도록 하고, 개시 전에도 등록할 수 있다.
무료 서비스만 운영하는 동안에도 사업 개시로 볼 여지가 있는지는 실제 운영 형태로 판단한다.
**수익을 만드는 순간(구독·광고 중 무엇이든) 등록이 먼저다.**

### 7-2. 수익을 만들기로 할 때 먼저 끝내야 하는 것

| 항목 | 이유 |
|---|---|
| 사업자등록 | 앱인토스 콘솔의 인앱 결제·인앱 광고 연동 조건 |
| 정산 정보 등록 | 수익 정산 계좌. 예금주명이 정확히 일치해야 한다 |
| 이용약관·환불 정책 | 유료 상품을 팔 때 필요 |
| 개인정보처리방침 갱신 | 결제·정산 정보 처리 항목 추가 |
| 통신판매업 신고 해당 여부 | 판매 형태에 따라 확인 |

### 7-3. 등록하면 따라오는 의무

- 부가가치세 신고 (간이과세자 연 1회 / 일반과세자 연 2회)
- 종합소득세 신고 (매년 5월)
- **개인정보처리자로서의 의무가 명확해진다** — 처리방침 공개, 안전조치, 유출 신고

### 7-4. 권고

수익을 만들기로 하면 **개인사업자(간이과세)로 시작한다.** 등록비 0원, 온라인 신청, 고정비 거의 없다.

### 7-5. 유료 전환을 하게 된다면 (보류)

개정 전자상거래법(2025-02-14 시행)의 다크패턴 규제는 **무료→유료 전환 전 30일 이내에 명시적 동의**를 받고,
가격·결제 방법·해지 방법을 고지하도록 한다. 묵시적 동의는 인정되지 않는다.
무료 서비스로 운영하는 동안에는 결제 UI 자체를 넣지 않으므로 이 절차가 발생하지 않는다.

### 7-6. 광고를 붙이는 경우 (검토 결과 — 지금은 불가)

| 사실 | 근거 |
|---|---|
| 외부 광고 네트워크(AdMob 등) 직접 연동은 **금지** | 앱인토스 서비스 오픈 정책 |
| 쓸 수 있는 것은 앱인토스가 주는 전면형·보상형·**배너** 광고뿐 | 같은 정책 |
| 인앱 광고 연동에 **사업자 정보 등록이 필수** | 인앱 광고 가이드 |
| 광고 수익은 약 30%가 운영비로 차감 | 인앱 광고 가이드 |
| **광고 카테고리·광고주를 제외하는 기능은 문서에 없다** | 인앱 광고 가이드에 해당 설명 없음 |

**식품 광고를 완전히 뺄 수 있는지 확인되지 않는다.** 원재료를 판정하는 화면 옆에 식품 광고가 붙으면
중립성이 무너지고, 사용자가 광고를 판정 결과로 오해할 수 있다(`docs/PRD.md` §8).
광고를 도입하려면 **사업자 등록 + 토스에 카테고리 제외 가능 여부 문의**가 먼저다.

## 8. 출시 전 체크리스트

- [ ] 개인정보처리방침 게시 (국외이전 항목 포함)
- [ ] 이용약관 게시 (면책 조항 포함)
- [ ] 업로드 화면에 국외이전 동의 절차
- [ ] **전송 전 확인 화면**이 건너뛸 수 없게 구현되어 있는지 확인
- [ ] 결과 화면 상단·하단 고지 문구 삽입
- [ ] 원재료명 출처 표기
- [ ] 알레르기 관련 별도 경고
- [ ] 결과 라벨이 **표시 위치**(앞쪽/중간/뒤쪽 표시 · 발견되지 않음 · 판단 보류)이고 권고형 어휘가 아닌지 확인
- [ ] **"많이 포함"·"소량 포함" 같은 함량 표현이 남아 있지 않은지** 확인
- [ ] **확인 불가 성분이 결과와 함께 표시**되는지 확인 (복합원재료·미등록 성분·판독 실패)
- [ ] 공공DB 조회 결과 중 **ORDNO가 없는 제품(C003·수입식품)** 에 위치 표시가 빠져 있는지 확인
- [ ] 이용약관에 **18세 이상** 조건이 있는지 (AI 제공자 약관)
- [ ] 유료 전환 고지 문구와 해지·환불 정책 (§7-5)
- [ ] 성분 카드 출처가 전부 **S~A급**인지. 기사·블로그·개별 논문이 섞이지 않았는지
- [ ] 성분 카드에 **단정형 문장**이나 *"논쟁이 있다"*·*"합리적이다"* 같은 우리 의견이 없는지
- [ ] 출처 링크가 **오픈 액세스**인지 (눌러서 실제로 읽히는지)
- [ ] **"인공 합성"** 같은 부정확한 표현이 없는지 (MSG는 발효 생산)
- [ ] 축 라벨이 **"초가공 지표"** 이고 **"위험 성분"** 이 아닌지
- [ ] `docs/refs/_index.md` 대장에 발행일·접근일·DOI가 기록됐는지
- [ ] Supabase 리전이 서울인지 확인
- [ ] **RLS 정책**이 적용됐는지. 익명·타 계정으로 교차 접근 시험
- [ ] **금지어 사전으로 전체 화면·문서·마케팅 문구 역검사**
- [ ] 결과 화면 캡처 한 장만 떼어놨을 때 "제품이 나쁘다"로 읽히지 않는지 확인
