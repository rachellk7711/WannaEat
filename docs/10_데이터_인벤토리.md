# 식품 데이터 인벤토리 전수 조사

> 작성자: Codex (OpenAI) · 작성자 표기일: 2026-09-16. 본문의 조사일은 당시 조사 기준일이다.

조사일: 2026-09-11 (KST) · 범위: 식품 원재료/표시/영양/첨가물/알레르기/바코드/회수/인증 및 이들과 직접 조인되는 업체·이력 데이터. 스키마 설계는 포함하지 않는다.

## 읽는 법과 검증 상태

- **실호출**은 식품안전나라의 공개 `sample` 키로 2026-09-11에 JSON을 받은 결과다. 샘플 엔드포인트는 요청 범위가 100이어도 5행만 반환했다. 따라서 `total_count`와 필드는 실제 응답에서 읽은 값이고, 5행으로 산출한 바이트 수는 표본 추정이다.
- **문서확인**은 공공데이터포털의 현재 Swagger/상세 페이지에서 읽은 값이다. 이 포털의 `sample` 키는 등록되지 않은 키로 거절되어 원본 행을 받지 못했다. 이 경우 총 건수·샘플 용량은 **확인 불가**라고 표기했다.
- 식품안전나라의 일반 URL 형식은 `https://openapi.foodsafetykorea.go.kr/api/{key}/{serviceId}/{json|xml}/{start}/{end}`이고, 파일은 `.../{key}/{serviceId}/file`이다. 포털 안내상 인증키는 식품안전나라 회원 후 자동 승인으로 발급되며, 서비스별 호출제한은 상세 페이지의 값이다. [이용 방법](https://www.foodsafetykorea.go.kr/api/howToUseApi.do)
- 아래의 “전체 필드”는 응답의 레코드(`row[0]` 또는 `item`) 필드다. 모든 REST 응답 공통 외피도 함께 기록한다: 식품안전나라는 `{SERVICE_ID:{total_count,row,RESULT{MSG,CODE}}}`, data.go.kr은 `{header{resultCode,resultMsg},body{items{item},numOfRows,pageNo,totalCount}}`.

```text

                                                    └─ 업종별 인허가/폐업 데이터

C005.BAR_CD ──────────────────── BAR_CD/BRCDNO/PDT_BARCD ─ I0490/I2620/I0320/FoodQR
```

# 과제 4 — 용량 추정

샘플은 각 서비스의 실제 JSON 5행 UTF-8 바이트 수 ÷ 5이다(공통 JSON 외피도 포함). 장문 텍스트가 많은 행은 이 표본보다 커질 수 있어 낙관치가 아니다.

|서비스|5행 표본 bytes|평균 B/행|총 건수|원문 JSON 환산|
|---|---:|---:|---:|---:|
|C002|1,995|399|1,073,137|408.3 MB|
|I1250|3,200|640|1,073,137|655.0 MB|
|C006|1,439|288|569,470|156.4 MB|
|C003|8,303|1,661|46,042|72.9 MB|
|C005|1,830|366|259,669|90.6 MB|
|I0950|4,207|841|6,895|5.5 MB|
|I1020|1,844|369|24,875|8.8 MB|
|I2520|2,692|538|43,612|22.4 MB|
|I0490|3,716|743|374|0.3 MB|
|I0580|1,867|373|39,268|14.0 MB|
|I2500|969|194|1,548,572|286.5 MB|
|합계 (위 11개만)|—|—|—|**약 1.72 GB**|

결론: 원문 수준으로만 이 11개를 보관해도 무료 500MB는 명백히 부족하다. `C002 + I1250` 중 중복 속성을 제거하더라도 원재료·제품·축산·건기식·바코드·업소를 함께 적재하면 무료 한도는 안전하지 않다. **Pro 8GB를 기준으로 잡되**, 수입 표시·FoodQR·영양DB의 실제 건수와 장문 필드(원재료/표시사항)를 받은 뒤 여유율을 재산정해야 한다. 이는 저장 정책이 아닌, 관측 표본에 의한 용량 판단이다.

# 과제 5 — 파일 일괄 다운로드 가능 여부

|데이터셋|전체 파일을 API 없이 한 번에?|근거 / 주의|
|---|---|---|
|`C002`, `I1250`, `C003`, `C005`|**예 (문서 확인)**|식품안전나라 상세에 CSV 다운로드와 `/api/{key}/{service}/file`가 명시. 파일 다운로드는 인증키당 서비스별 1일 10회.|
|`C006` 및 기타 식품안전나라 서비스|**확인 필요**|포털은 서비스별 CSV 버튼 구조이나 각 상세 파일 탭을 실키로 검증하지 못함.|
|`15127578` 식품영양성분DB|**예 (문서 확인)**|공공데이터포털이 “식품영양성분DB 통합 자료집” 파일을 함께 제공. API와 파일의 동일성·최신일은 적재 전 대조 필요.|
|`15100064/65/66` 전국통합영양 표준데이터|**예 (문서 확인)**|CSV 표준데이터 다운로드.|
|`15098434` 수입식품 제품 목록|**예 (문서 확인)**|연도별 CSV 직접 다운로드; 2019~2025 분할 파일.|
|`15110213/14`, `15111777`, `15111913`, `15143798`, `15073949`|**확인 불가**|현재 상세 페이지에서 REST 명세는 확인했지만 전체 파일 다운로드 여부는 실키/다운로드 화면으로 검증하지 못했다. API 페이징을 전제로 계획하면 안 된다.|

## 아키텍처 설계에 반드시 반영해야 할 제약 5가지

1. 국내 가공식품 원재료는 `C002`의 **쉼표 문자열**이며, 원재료 코드가 함께 오지 않는다. 표준 원재료 마스터와의 연결은 확정 FK가 아니다.
2. `C002/I1250`은 포털 고지상 **2017년 이후 내수·겸용** 범위다. “국내 전 제품/전 기간”이라고 표시하면 안 된다.
3. 바코드 `C005`는 제공기관이 **2018년 이후 최신화 중단**을 명시했다. 바코드→제품 매칭은 신뢰도/최종확인일을 가져야 한다.
4. 알레르기 구조화 데이터는 일반 품목제조보고에 없다. FoodQR의 알레르기 API는 유력하지만 실제 키로 응답·커버리지·조인키를 검증하기 전 필수 의존성으로 삼을 수 없다.
5. 대량 초기 적재는 API 페이징이 아니라 **파일 다운로드 우선**이다. 파일도 서비스별 1일 10회 제한이 있고, 식품안전나라 API는 제한 운영·시간대 오류(`ERROR-503`) 가능성이 있으므로 재시도/증분 동기화 전제가 필요하다.
