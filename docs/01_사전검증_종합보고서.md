## 헤드라인 발견 — 페인포인트와 데이터가 정확히 맞물렸다

이 조사의 가장 중요한 결과는 **V3가 찾은 최대 고통과 V4가 찾은 데이터가 완벽히 대응한다는 것**이다.

### V3가 찾은 것 — 커뮤니티는 순탄수 계산으로 고통받는다

> **"탄수 20 - (에리스리톨 6 + 알룰로오스 2 + 식이섬유 8) = 4g 이라 보면 되는게 맞아요?"**
> — 「순탄수 계산법 좀 확실히 알려주실분」

> **"원재료명에는 알룰로스가 앞에적혀잇긴한데 / 영양정보에는 알룰로스가 따로없음? / 이경우 그냥 저 탄수화물이 순탄수라고 봐야됨? / 아니면 그냥 추정불가인가?"**
> 댓글: **"이거보고 유추하는수밖에업ㅅ음"**

유튜브 「저탄고지 식품 영양성분표 보는 법」(조회 21,302)에는 **영상을 보고도 계산을 못 하는 댓글이 줄줄이** 달려 있다.

### V4가 찾은 것 — 그 계산에 필요한 데이터가 공공DB에 있다

**식품영양성분DB (`data.go.kr/data/15127578`)** 의 컬럼:

| 컬럼 | 내용 |
|---|---|
| `AMT_NUM6` | 탄수화물(g) |
| `AMT_NUM7` | 당류(g) |
| `AMT_NUM8` | **식이섬유(g)** |
| `AMT_NUM53` | **당알콜(g)** |
| `AMT_NUM55` | **알룰로오스(g)** |
| `AMT_NUM56` | **에리스리톨(g)** |
| `AMT_NUM95/96` | 카프르산(10:0) / 카프릴산(8:0) — **MCT 지표** |
| `ITEM_REPORT_NO` | **품목제조보고번호 (조인키)** |

> **순탄수 = 탄수화물 − 식이섬유 − 당알콜**
>
> **이 계산에 필요한 컬럼이 전부 있고, 알룰로오스·에리스리톨이 개별 컬럼으로 분리되어 있다.**
> 커뮤니티가 손으로 유추하던 것을 **정확히 자동 계산할 수 있다.**

**이것이 이 제품의 핵심 기능이 되어야 한다.** 원재료명 대조는 그 다음이다.

## V3 — 커뮤니티 수요: 상(高)

### ✅ 수요 증명 — 우리가 만들려는 것이 이미 "게시판"으로 존재한다

**국내 최대 키토 카페(회원 303,723명)에 「성분 질문게시판」 전용 게시판이 있다.** 공지 문구:

> **"질문 전 공지확인 필수. 성분표 첨부 필수."**

`성분 질문게시판`과 `(구)성분 질문게시판`이 **둘 다** 존재 — 이 질문 유형만으로 게시판 하나가 10년 가까이, 한 번 갈아엎을 만큼 누적됐다.

**"라벨 사진을 올린다 → 고인물이 판정해준다"가 제도화된 워크플로다. 우리 제품은 이 게시판의 자동화다.**

| 커뮤니티 | 규모 |
|---|---|
| 저탄수화물 고지방 - 키토제닉 다이어트 카페 | **회원 303,723명** / 게시글 452,684 |
| 저탄고지 라이프스타일 (LCHF) 카페 | 회원 63,814명 |
| 디시 저탄고지 마이너 갤러리 | 일 수십 건, 매일 활성 |
| 유튜브 | 만~십만 구독자 채널 20개+ |

대체당 영상 조회수: 「대체감미료 11종 총정리」 **35.7만회**, 「절대 사용하지 말아야 할 당류」 **26.3만회**.

**카니보어는 수천~1만 규모**로 키토보다 1~2자리 작다 → **1차 모드는 저탄고지 중심으로 확정.**

### ✅ 우리 접근법이 이미 검증됐다 (극소수만 쓰는 방법)

커뮤니티 고급 사용자가 **이미 품목제조보고 DB를 손으로 조회**하고 있다:

> **"품목보고번호조회하니까 1 닭고기 2 소스 3 돼지고기 4 정제수 5 곡류가공품 6 전분 … 22 향신료조제품 이렇게 함량많은대로 들어가있는데 이거보고 유추하는수밖에업ㅅ음"**

그런데 **갤러리 내 "식품안전나라"·"품목보고번호" 검색 결과는 0건** — 이 방법을 아는 사람은 극소수다. **자동화 여지가 정확히 여기 있다.**

### 🔴 최대 경고 — 유사 앱이 이미 전멸했다

### AI 챗봇이 이미 1차 도구다 — 그리고 그것이 우리의 진입 지점이다

디시 입문자 가이드 **0번 항목**:
> **"0. 일단 제미나이, GPT한테 물어봐라 / ex) 이거 먹어도됨?"**

실사용 패턴은 **AI 1차 → 커뮤니티 2차 검증**:
> **"제미니는 먹어도 된다는데 / 선생님들이 보시기엔 어떤가요"**

**그러나 신뢰 문제가 명확하다:**
> **"AI한테 물어봤는데 신뢰가 안가네 / 말을 중의적으로 하니까;;"**

> **→ "AI로 판별"만으로는 차별점이 없다. 무료 AI가 이미 그 자리에 있다.**
> **차별점은 「결정론적 룰셋 + 정부 데이터 출처 + 항상 같은 답」이다.** AI가 못 주는 것이 정확히 그 셋이다.

### 부정확한 민간 규칙이 지배하고 있다

> **"하 어디서 ~톨은 다 걸러라 얘기 듣고 알룰로스랑 스테비아만 괜찮은 건줄 알고… 복부팽창과 가스 원인이 이거엿군요"** (👍14)
> **"~톨 자로 끝나는 대체당은 다 안좋다고 해서 에리스리톨 들어간 제품들은 멀리했었어요!! 근데 알고보니 그렇지 않았네요"** (👍9)

두 개의 민간 규칙 — **"~톨이면 걸러라"**, **"~오스면 탄수화물"** — 은 접미사 패턴 매칭이라 부정확하다(알룰로스는 -ose지만 수용, 에리스리톨은 -tol이지만 논쟁). **정확한 판별 도구의 공백을 직접 증명한다.**

### ★ 회피 축이 두 개다 (설계 직결)

| 축 | 내용 |
|---|---|
| **(a) 탄수화물 은닉** | 표시 뒤에 숨은 당류·전분 — 말토덱스트린, 전분, 물엿 |
| **(b) 초가공·첨가물** | 화학첨가물·정제유지 — 카놀라유, MSG, 카라기난 |

**두 축은 독립적이다:**
- **잔탄검**: (a) 무해 + (b) **재평가로 허용** — *"검류나 펙틴은 프리바이오틱스로 장건강을 위해 따로 먹는 사람들도 있을정도"*
- **카놀라유**: (a) 무해하지만 (b)로 **거부**
- **말토덱스트린**: (a)(b) 모두 위반

> **→ 판정을 두 축으로 분리해 표시해야 한다.** 단일 점수로 뭉개면 잔탄검과 말토덱스트린이 같은 칸에 들어간다.
> **룰셋 스키마에 `axis` 필드를 추가한다.**

### 판정 기준이 파편화되어 있다 — 우리 설계를 검증한다

같은 제품에 "안됨"과 "괜찮음"이 동시에 달린다. 클린키토 / 더티키토 / 카니보어가 다른 기준을 쓴다.

> **"이거 먹어도 됨? → 먹어도 됨 / 이거 먹으면 안됨? → 먹으면 안됨 / 사실 우리는 먹어도 되는거랑 먹으면 안되는거 다 알고있음"**

**→ 단일 정답 판정기는 이 집단과 맞지 않는다. "내 기준 등록 → 대조" 구조가 옳다.** 우리 모드 설계가 정확히 그것이다. **다만 같은 구조로 실패한 앱이 둘 있다(세이프리스트·Chomp) — 구조가 옳은 것과 사업이 되는 것은 별개다.** *(2026-09-11 정정: 두 앱은 실패 사례가 아니다 — 출시 11일 / 한국 미진입. 단 "구조가 옳은 것과 사업이 되는 것은 별개"라는 결론은 엄선 사례로 유지된다)*

### 커뮤니티가 기피하는 성분 (룰셋 구축 순서)

> **⚠️ 이 표의 출처는 커뮤니티 발화이며, 과학적 합의가 아니다.**
> V3가 디시 갤러리·유튜브 댓글·카페 게시글에서 추출한 것으로 정량 조사가 아니다.
> 예: **카놀라유 기피는 주류 영양학과 대립한다.** 우리가 이것을 "기피 성분"으로 단정하면 안 된다.
> 상세는 아래 **§데이터 3계층 원칙** 참조.

## ★ 데이터 3계층 원칙 — 어디까지가 사실이고 어디부터가 의견인가

이 제품에서 가장 중요한 설계 원칙이다. **계층을 섞으면 법적 리스크가 되고, 분리하면 차별점이 된다.**

가장 선명한 증거는 V3가 찾은 이것이다:

> **수크랄로스 — 주류 의학 채널은 긍정, 키토 커뮤니티는 장내미생물 근거로 회피. 정반대.**

**같은 성분인데 출처에 따라 판정이 뒤집힌다.** "정답"이 없으므로 출처를 밝히지 않으면 안 된다.

| 계층 | 내용 | 출처 | 우리가 단정해도 되나 |
|---|---|---|---|
| **① 사실** | 이 성분은 무엇인가 — 용도(감미료·보존료·증점제), 화학적 정체 | ~~식약처 식품첨가물 정보 API~~ → ⚠️ **2026-09-14 정정: 그 API는 식품 유형별 기준·규격이고 용도가 없다.** 「식품첨가물의 기준 및 규격」 고시에서 가져온다 (`04_성분사전_구축계획`) | ✅ 정부 자료 |
| **② 정량** | 순탄수는 얼마인가 — 탄수·식이섬유·당알콜 g수 | **식품영양성분DB (15127578)** | ✅ 산수 |
| **③ 기준** | 이게 내 식단에 맞나 — 말티톨 거부, 카놀라유 기피 | **커뮤니티 통념 / 사용자 설정** | ❌ **절대 안 됨** |

### ①②만으로도 제품이 성립한다

> "이 제품에는 감미료 3종이 들어있고, 그중 하나는 당알콜입니다. 순탄수는 4.2g입니다."

**전부 사실 진술이다.** 비방도 효능 표방도 아니다. 그리고 커뮤니티가 손으로 유추하던 것을 정확히 대신해준다.

### ③은 우리 것이 아니다 — 출처를 귀속시킨다

```
❌ "말티톨 — 기피 성분"

✅ "말티톨 — 당알콜류 감미료 (식약처 분류)
    · 저탄고지 커뮤니티에서는 일반적으로 제외 대상으로 분류됩니다  [근거 보기 →]
    · 회원님 기준: 제외 설정됨  [수정]"
```

`[근거 보기]`는 V3가 수집한 **실제 발화와 URL**을 보여준다. 우리가 판정한 것이 아니라 *"커뮤니티에서 이렇게 말하고 있다"* 를 제시하는 것이다.

이는 `02_법무-표현설계.md` §3-3의 원칙과 동일하다 — *"출처를 커뮤니티 통념으로 돌리고 단정하지 않는다."*

### 이 구조가 차별점이 된다

*(2026-09-11: "전멸"은 정정됨 — `docs/11`)* 기존 앱들과 갈라지는 지점이 여기 있다. **단일 점수를 주는 앱은 "왜?"에 답할 수 없다.** 우리는 계층마다 출처가 다르다는 것을 드러낸다:

- 순탄수 4.2g → **정부 데이터**
- 감미료 3종 → **식약처 분류**
- 이게 맞는지 → **회원님 기준. 커뮤니티는 이렇게 봅니다**

규모가 커지면 ③계층을 **커뮤니티 투표로 갱신**할 수 있다. 논쟁 성분(에리스리톨·수크랄로스)일수록 여론이 갈리는데, **그 분포 자체를 보여주는 것이 정확하다.**

### 🔴 확인해야 할 구멍 — ①계층의 근거가 불확실하다

식약처 **식품첨가물 정보 API**의 필드는 `첨가물명 · 화학식 · 정의 · 성분규격 · 확인시험 · 순도시험 · 정량법` 이다.
**`용도`(감미료/보존료/증점제) 필드가 명시적으로 없다.**

`정의` 필드 안에 용도가 서술되어 있을 가능성이 있으나 **확인되지 않았다.**
→ ①계층 전체가 여기 달려 있으므로 **개발 1주차 확인 항목으로 승격한다.**
→ 없다면 대안: 식품첨가물 공전 본문(법령) 파싱, 또는 용도 분류를 직접 구축.

> ✅ **2026-09-14 확인 완료 — 구멍이 사실로 드러났다.**
> `apis.data.go.kr/1471000/FoodAdtvInfoService01` 실호출 결과, 이 API는 **첨가물 정보가 아니라 식품 유형별 기준·규격**이다 (예: `{"PC_KOR_NM":"과자","T_KOR_NM":"세균수","SPEC_VAL":"10,000이하"}`, 32,746건). 용도 필드가 없고, 공공데이터포털 `15058807`도 같은 엔드포인트다.
> → **대안 채택:** 「식품첨가물의 기준 및 규격」 고시 본문 + `I1020` 식품원재료 정보 + 자체 구축. 상세는 `04_성분사전_구축계획.md`

## V1 — Gemini 라벨 OCR: 중

### 크롭이 정확도의 핵심 (법무와 결론이 수렴)

Gemini는 이미지를 768×768 타일로 처리하고 토큰 상한이 있다(`high` = 1120토큰). **4000×3000 사진을 통째로 보내도 유효 해상도는 제한된다.** 해상도를 올리는 것보다 **원재료명 영역만 크롭해 토큰 예산을 독점**시키는 것이 훨씬 효과적이다.

> **`02_법무-표현설계.md` §5-2에서 개인정보 때문에 크롭을 필수로 정한 것과 결론이 같다.**
> **두 이유가 수렴하므로 크롭 강제는 타협 대상이 아니다.**

### VLM은 못 읽으면 조용히 지어낸다

NeurIPS 2025 KIE-HVQA: MLLM은 블러·가림·저대비에서 열화를 지각하지 못하고 **언어적 사전지식에 과의존해 환각을 생성**한다.

한국어 실사용 실패 유형:
- **중간 누락** — 표 항목이 빠졌는데 **시작과 끝은 정확해서 발견되지 않음**
- **환각** — "추가적 업무를" → "주인의식을 발휘하여 적극적으로 업무를"
- **1글자 오인식으로 의미 반전** — "AI 평가 안함" → "AI**가** 평가 안함"

`정제소금`, `산도조절제`, `혼합제제` 같은 고빈도 도메인 어휘는 **모델이 문맥만으로 그럴듯하게 만들어낼 수 있다.**

> **→ 신뢰도 게이트 필수.** 성분 사전 매칭률 + `legibility` 자기보고 + 2회 호출 diff를 조합해 임계 미달 시 **판정하지 않고 원문을 보여주며 사용자 확인을 받는다.**

### ⚠️ Gemini 무료 티어 약관이 서비스와 충돌한다

[Gemini API 추가 약관](https://ai.google.dev/gemini-api/terms):
> 무료 할당량은 제출 콘텐츠를 **제품 개선·ML 학습에 사용**하며 **인간 검토자가 읽고 주석할 수 있다.**
> **"민감정보·기밀정보·개인정보를 무료 서비스에 제출하지 말 것."**

**→ 베타라도 실사용자를 받는 순간 유료 티어 전환을 검토해야 한다.** 예산에 반영 필요.

## V2 — 제품명 매칭: 상(高) 난도

**"장바구니 캡처 한 장 → 자동 판정" 그림은 성립하지 않는다.** 초기 자동확정률 30~50% 추정.

```
[비알칼리] 제로 무설탕 다크초콜릿 100% 건강한 간식, 500g
  → 정규화 후 core: "다크초콜릿"
  → 매칭되는 품목: 수백 건
```

**노이즈를 지우면 일반명사만 남는다.** 브랜드·제조사·식품유형·규격 없이는 1:1 확정이 원리적으로 불가능하다.

### 정규화는 삭제가 아니라 필드 분해로

```
raw_title
 → S0 유니코드 정규화 (NFC, 전각→반각, lower)
 → S1 플랫폼 아티팩트 제거
 → S2 옵션 꼬리 분리       → qty     ← 쿠팡은 "제품명, 옵션, 수량" 구조. 첫 쉼표 앞만 취해도 효과 큼
 → S3 브래킷 분해          → seller / attr
 → S4 수량·규격 추출       → spec    ← 92%, C8, 500ml는 변별에 결정적. 지우면 안 됨
 → S5 배송·프로모션 제거
 → S6 마케팅·효능 토큰 분리 → attr   ← 가중치 0.2~0.3으로 재투입
 → S7 브랜드 후보 추출     → brand   ← 사전 룩업
 → S8 토큰 정리·중복 제거  → core_name
```

**띄어쓰기 비의존화:** 공백 제거 `nospace_key`를 함께 저장 → `MCT오일`↔`MCT 오일` 해결.
**네이버 쇼핑 상품명 금지 수식어 목록**을 그대로 제거 대상 사전으로 재활용 가능.

### 브랜드는 필터가 아니라 가산점

`BSSH_NM`은 **제조업소명**이다. 유통 PB(쿠팡 곰곰, 노브랜드)는 OEM이라 상품명 브랜드와 구조적으로 불일치한다.
> **`BSSH_NM`을 AND 조건으로 걸면 PB·OEM 상품이 전멸한다.** 후보 생성은 품목명만으로, 브랜드는 리랭킹 가중치(+0.15~0.25)로만.

### 오류 비용이 비대칭이다 — 정밀도 우선

```
못 찾음  → "정보 없음"에 그침
잘못 찾음 → 엉뚱한 제품의 원재료 → 건강 오판
```

| 구간 | 조건 | 동작 |
|---|---|---|
| 자동 확정 | score ≥ 0.90 **AND** 브랜드 일치 **AND** 식품유형 일치 **AND** (top1−top2) ≥ 0.10 | 표시 + 근거 배지 |
| **사용자 확인** | 0.55 ≤ score < 0.90 또는 동점 | **후보 3~5개 제시** |
| 매칭 실패 | score < 0.55 | "확인 불가" + 라벨 촬영 유도 |

**마진 규칙이 임계값보다 중요하다.** `설탕대신 알룰로스`처럼 동일 품목명이 여러 업소에 존재하면 top1·top2가 동률이다. **점수가 높아도 마진이 없으면 자동확정 금지.**

**식품유형 하드 게이트:** `초콜릿` vs `초콜릿가공품` vs `준초콜릿` vs `캔디류`는 원재료 구성이 완전히 다르다.

### ⚠️ pg_trgm의 한글 지원이 보장되지 않는다

`KEEPONLYALNUM` 매크로 때문에 빌드 옵션에 따라 한글 트라이그램이 생성되지 않을 수 있다.

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
SELECT show_trgm('초코파이');   -- 빈 배열이면 한글 미지원
SELECT similarity('초코파이', '오리온 초코파이 정');
```

**→ 개발 1주차 최우선 확인 항목. 여기서 막히면 매칭 아키텍처를 다시 짜야 한다.**

### alias 캐시가 가장 효과 큰 패턴

사용자가 후보를 고른 순간 `(정규화 상품명 → 품목보고번호)`를 저장하면 이후 정확 조회로 전환된다. **쇼핑몰 상품명은 롱테일이지만 인기 상품은 극단적으로 편중**되므로 수백~수천 건만 쌓여도 자동확정률이 급등한다.

| ③ **무료 대체재가 충분 (커뮤니티 + 무료 AI)** | **치명적. 지불의사 자체가 없다는 뜻** |
| ④ 실행 품질 (언라벨 평점 1.0) | 극복 가능 |

**→ 실패한 앱 7개를 직접 설치·사용해 원인을 규명해야 한다. 개발 착수 전 필수.**

> ⚠️ **2026-09-11 결과** (`docs/11`): ①② 판단 불가·증거 없음, ③ 미해결, ④ 확정(언라벨), **⑤ 수익 구조 추가 — 가장 유력** (엄선: 무료로 50만 모은 뒤 소비자 과금 없이 판매자 수익으로 가다 폐업). 국내 앱 직접 테스트는 사용자 작업으로 남음.
